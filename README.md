# WatchStore Bot – בוט ידע ארגוני (RAG)

בוט שעונה לחנויות הלקוח של WatchStore על שאלות לגבי הקטלוג, הזמנות, משלוחים, תשלום, אחריות ושימוש במערכת. הבוט עונה **רק** מתוך מסמכי החברה שבתיקייה `data/`. כשאין במסמכים תשובה, הוא אומר שלא מצא מידע ומפנה לשירות הלקוחות.

## איך זה עובד

```
טעינה (ingest.py, פעם אחת):
  data/*.md|pdf|docx|txt → SentenceSplitter (512 טוקנים, חפיפה 64)
  → gemini-embedding-001 → ChromaDB (cosine) בתיקייה chroma_db/

שאלה (bot.py, בכל הודעה):
  שאלה + היסטוריה → condense: ניסוח מחדש כשאלה עצמאית (רק אם יש היסטוריה)
  → embedding של השאלה → חיפוש Top-K=4 ב-ChromaDB
  → סינון לפי cosine ≥ 0.55
  → אין קטעים? תשובה קבועה "לא מצאתי מידע", בלי לפנות ל-LLM
  → יש קטעים? gemini-3.5-flash-lite עונה רק מתוכם + רשימת מקורות
```

## החלטות התכנון

| # | נקודת החלטה | הבחירה | נימוק |
|---|---|---|---|
| 1 | Vector DB | **ChromaDB** (PersistentClient, שמירה לדיסק) | נלמד בכיתה, רץ מקומית בלי שרת, מתאים לכמות מסמכים קטנה |
| 2 | ספרייה | **LlamaIndex** | דרישת התרגיל. משמש לטעינה, חלוקה, אינדקס ושליפה |
| 3 | אופן החלוקה | **לפי טוקנים** – `SentenceSplitter`, ‏chunk של 512 טוקנים | זול ומהיר. חלוקה סמנטית דורשת embedding לכל משפט ולכן יקרה יותר. `SentenceSplitter` לא חותך באמצע משפט, כך שמתקבל חלק מהיתרון של חלוקה לפי משמעות |
| 4 | חפיפה בין chunks | **כן, 64 טוקנים (12.5%)** | מידע שנופל על גבול בין שני chunks לא הולך לאיבוד |
| 5 | API Key | **Gemini** (Google AI Studio) | יש מכסה חינמית שמספיקה לפרויקט כזה |
| 6 | Top-K | **4** | המסמכים קצרים וממוקדים. 4 קטעים מכסים שאלה שנוגעת בשני נושאים, בלי להעמיס על המודל קטעים לא רלוונטיים |
| 7 | מודלים | embedding: **gemini-embedding-001**, תשובה: **gemini-3.5-flash-lite** | embedding רב-לשוני שתומך היטב בעברית. Flash-Lite הוא המודל הזול והמהיר, ומספיק לניסוח תשובה מתוך קטעים שכבר נשלפו |
| 8 | הרחבת שאלה | **כן – condense question** | שאלת המשך כמו "ומה לגבי החזרות?" מנוסחת מחדש כשאלה מלאה לפי ההיסטוריה, לפני ה-embedding. בשאלה הראשונה בשיחה אין קריאה נוספת ל-LLM |
| 9 | צורת החיפוש | **Cosine similarity** עם סף מינימלי 0.55 | Cosine מתאים ל-embeddings של טקסט. הסף מונע תשובה מקטעים שלא באמת קשורים לשאלה, וזה מה שגורם לבוט לא לענות מחוץ לידע הארגוני |
| – | קליינט | **Gradio** (`ChatInterface`, RTL) | הכי פשוט, ממשק צ'אט מוכן עם היסטוריה |

כל הערכים האלה ניתנים לשינוי בקובץ `.env` בלי לגעת בקוד.

## הרצה מקומית

```bash
cd watchstore-bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

לפתוח את `.env` ולהכניס את המפתח מ-https://aistudio.google.com/apikey ב-`GOOGLE_API_KEY`.

```bash
python ingest.py
python app.py
```

הבוט עולה ב-http://localhost:7860. אם מדלגים על `ingest.py`, האפליקציה בונה את האינדקס לבד בעלייה הראשונה.

**אחרי כל שינוי במסמכים ב-`data/` צריך להריץ שוב `python ingest.py`.** הסקריפט מוחק את ה-collection ובונה אותו מחדש, כך שאין כפילויות.

## המסמכים הארגוניים

| קובץ | תוכן |
|---|---|
| `01_אודות_החברה.md` | מי העסק, סוגי המשתמשים, החנויות, פרטי קשר |
| `02_קטלוג_השעונים.md` | קטגוריות, תגיות, הדגמים והמחירים (תואם ל-seed של השרת) |
| `03_מדיניות_הזמנות.md` | ביצוע הזמנה, מלאי לא מספיק, התנגשות (409), סטטוסים |
| `04_משלוחים_ותשלום.md` | זמני משלוח, דמי משלוח, תנאי תשלום, הנחות כמות |
| `05_אחריות_והחזרות.md` | אחריות, החזרת שעון פגום או תקין, תיקונים |
| `06_שימוש_במערכת_ושאלות_נפוצות.md` | הרשמה, התחברות, חיפוש, שאלות נפוצות |

הקטלוג, החנויות, הסטטוסים והתנהגות המערכת לקוחים מהקוד של WatchStore. מדיניות המשלוחים, התשלום, האחריות וההחזרות ופרטי הקשר של העסק הם **נתוני דוגמה** – אפשר לערוך אותם או להוסיף מסמכים משלך (גם PDF ו-Word).

## כיול סף הדמיון

בסוף כל תשובה מוצגים קובצי המקור שממנה נלקחה. אם הבוט עונה "לא מצאתי" על שאלה שהתשובה שלה כן נמצאת במסמכים – להוריד את `SIMILARITY_CUTOFF` (למשל ל-0.5). אם הוא עונה על שאלות שלא קשורות לעסק – להעלות אותו.

הערה טכנית: ה-`ChromaVectorStore` של LlamaIndex מחזיר ציון `exp(-distance)` ולא את ה-cosine עצמו. ב-`bot.py` הפונקציה `to_cosine` ממירה אותו חזרה (`cosine = 1 + ln(score)`), כך שהסף שמוגדר ב-`.env` הוא cosine similarity אמיתי.

## פריסה ל-Render

הקובץ `render.yaml` מגדיר Web Service של Python. ב-Render מגדירים את `GOOGLE_API_KEY` במשתני הסביבה. בתוכנית החינמית הדיסק לא נשמר בין הפעלות, ולכן האינדקס נבנה מחדש בכל עלייה של השירות (כמה שניות, כ-20 chunks שעוברים embedding).
